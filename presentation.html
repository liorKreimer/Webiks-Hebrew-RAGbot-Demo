02 · What we built

Hybrid BM25 + Dense, fused by rank

Fuse the existing dense ranking with a new BM25 query on the same indexed text, via weighted Reciprocal Rank Fusion. No reindexing. No new model. No new dependency — BM25 is native to Elasticsearch.

1 · Build & evaluate

Iterated unweighted → weighted RRF after v1 reshuffled good rank-1 answers. Evaluated on 30 held-out questions, never seen in training.

dense 2 · bm25 1 (final)
2 · Review & harden

Code review caught a real scoring bug — double-counting in the fusion math. Fixed, unit-tested, and re-evaluated before integration.

One setting — RETRIEVAL_MODE=hybrid. The dense path stays untouched, byte-for-byte, covered by regression + unit tests.

Honest limitation

Long, low-specificity questions can make BM25 match most of the index, diluting rather than sharpening the signal (one case above) — and a few already-correct rank-1 results shift down elsewhere in the set. A Hebrew-aware analyzer and query tuning are the natural next steps — not attempted here given time constraints.
